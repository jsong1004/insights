# Cloud Build Variable Reference

## Variable Types and Escaping Rules

### 1. Built-in Variables (Single `$`)

Cloud Build provides built-in variables that are automatically available:

```yaml
- '--project=$PROJECT_ID'         # Current project
- '--tag=$SHORT_SHA'               # Short commit SHA
- '--branch=$BRANCH_NAME'          # Git branch name
- '--repo=$REPO_NAME'              # Repository name
```

**Built-in Variables:**
- `$PROJECT_ID` - GCP project ID
- `$BUILD_ID` - Unique build ID
- `$PROJECT_NUMBER` - GCP project number
- `$COMMIT_SHA` - Full commit SHA
- `$SHORT_SHA` - Short commit SHA (7 chars)
- `$REPO_NAME` - Repository name
- `$BRANCH_NAME` - Git branch name
- `$TAG_NAME` - Git tag name
- `$REVISION_ID` - Git revision

### 2. Custom Substitutions (Single `$` with `_` prefix)

Define custom variables in the `substitutions` section:

```yaml
substitutions:
  _SERVICE_NAME: 'my-service'
  _REGION: 'us-west1'
  _MEMORY: '4Gi'

steps:
  - name: 'gcr.io/cloud-builders/gcloud'
    args:
      - 'run'
      - 'deploy'
      - '${_SERVICE_NAME}'        # Use with ${_VAR} syntax
      - '--region=${_REGION}'
      - '--memory=${_MEMORY}'
```

**Custom Substitution Rules:**
- Must start with underscore: `_VAR_NAME`
- Use `${_VAR_NAME}` syntax in YAML
- Can be overridden via command line:
  ```bash
  gcloud builds submit --substitutions=_SERVICE_NAME=custom-name
  ```

### 3. Bash Script Variables (Double `$$`)

When writing bash scripts in Cloud Build, escape variables with `$$`:

```yaml
steps:
  - name: 'gcr.io/cloud-builders/gcloud'
    entrypoint: 'bash'
    args:
      - '-c'
      - |
        # ❌ WRONG - Cloud Build tries to substitute $SERVICE_URL
        SERVICE_URL=$(gcloud run services describe my-service)

        # ✅ CORRECT - Double $$ becomes single $ in bash
        SERVICE_URL=$$(gcloud run services describe my-service)
        echo "URL: $$SERVICE_URL"
```

**Bash Variable Rules:**
- Use `$$` for bash variables: `$$VAR`, `$$MY_VALUE`
- Cloud Build converts `$$` → `$` when executing bash
- Prevents Cloud Build from treating bash vars as substitutions

### 4. Environment Variables in Container

For environment variables passed to containers:

```yaml
steps:
  - name: 'gcr.io/cloud-builders/docker'
    args: ['build', '-t', 'image', '.']
    env:
      - 'MY_VAR=value'              # Simple string
      - 'PROJECT=$PROJECT_ID'       # Built-in variable
      - 'SERVICE=${_SERVICE_NAME}'  # Custom substitution
```

## Common Patterns

### Pattern 1: Mixing Variable Types

```yaml
steps:
  - name: 'gcr.io/google.com/cloudsdktool/cloud-sdk'
    entrypoint: 'bash'
    args:
      - '-c'
      - |
        # Built-in variable (single $)
        echo "Project: $PROJECT_ID"

        # Custom substitution (single $ with braces)
        echo "Service: ${_SERVICE_NAME}"

        # Bash variable (double $$)
        RESULT=$$(gcloud run services list --format=json)
        echo "Result: $$RESULT"
```

### Pattern 2: Conditionals in Bash

```yaml
- name: 'gcr.io/cloud-builders/gcloud'
  entrypoint: 'bash'
  args:
    - '-c'
    - |
      if [ "${_ENV}" = "production" ]; then
        REPLICAS=3
      else
        REPLICAS=1
      fi

      echo "Deploying with $$REPLICAS replicas"
      gcloud run deploy ${_SERVICE_NAME} --min-instances=$$REPLICAS
```

### Pattern 3: Service URL Retrieval

```yaml
- name: 'gcr.io/google.com/cloudsdktool/cloud-sdk'
  entrypoint: 'bash'
  args:
    - '-c'
    - |
      # Get service URL (bash variable)
      SERVICE_URL=$$(gcloud run services describe ${_SERVICE_NAME} \
        --region=${_REGION} \
        --project=$PROJECT_ID \
        --format="value(status.url)")

      # Test the service
      HTTP_CODE=$$(curl -s -o /dev/null -w "%{http_code}" "$$SERVICE_URL/health")

      if [ "$$HTTP_CODE" = "200" ]; then
        echo "✅ Service is healthy at $$SERVICE_URL"
      else
        echo "❌ Health check failed with code $$HTTP_CODE"
        exit 1
      fi
```

## Troubleshooting

### Error: "unused substitution"

```
ERROR: key in the template "MY_VAR" is not a valid built-in substitution
```

**Cause:** Using `$MY_VAR` or `${MY_VAR}` without defining it

**Solution:** Either:
1. Add to substitutions: `_MY_VAR: 'value'`
2. Escape for bash: `$$MY_VAR`
3. Use built-in variable if applicable

### Error: "invalid substitution key"

```
ERROR: invalid value for 'build.substitutions': key must start with '_'
```

**Cause:** Custom substitution doesn't start with underscore

**Solution:** Rename `MY_VAR` → `_MY_VAR`

### Bash Script Not Working

**Problem:** Variables empty or literal `$VAR` printed

**Cause:** Forgot to escape with `$$`

**Solution:** Replace `$VAR` with `$$VAR` in bash scripts

## Quick Reference Table

| Type | Syntax | Example | When to Use |
|------|--------|---------|-------------|
| Built-in | `$VAR` | `$PROJECT_ID` | Cloud Build variables |
| Custom | `${_VAR}` | `${_SERVICE_NAME}` | User-defined values |
| Bash | `$$VAR` | `$$SERVICE_URL` | Bash script variables |
| Env Var | `VAR=value` | `DEBUG=true` | Container environment |

## Best Practices

1. **Prefix custom substitutions** with underscore: `_MY_VAR`
2. **Use braces** for clarity: `${_VAR}` instead of `$_VAR`
3. **Always escape** bash variables with `$$`
4. **Document substitutions** at the top of cloudbuild.yaml
5. **Validate locally** before submitting:
   ```bash
   python3 -c "import yaml; yaml.safe_load(open('cloudbuild.yaml'))"
   ```
